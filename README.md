# VideoML player

Legacy `mountVmlPlayer` and `createVmlPlayerController` continue to accept XML without frozen timing. For a generated project, use `createVerifiedVmlPlayerController(container, {xml, resolvedTiming}, loadSegmentAudio, loadCompositionAudio)`. The async call validates frozen IDs and timing, verifies each segment and assembled composition WAV, then mounts. It keeps one verified Blob-backed audio owner per sync group; seek, pause and disposal control that audio. A frozen React `VideomlDomPlayer` requires the equivalent `resolvedTiming`, `loadAudio`, and `loadCompositionAudio` props when narration exists.

Frozen playback removes source `<audio>` elements, rejects source scripts and event handlers, and mutes source `<video>` elements while retaining their visual source. Local preview can change non-timing visual content with the same ordered IDs; P17 portable bundles bind source and artifacts with manifest hashes. Frozen timing supplies transition and child visibility intervals, but the DOM player does not yet provide renderer-equivalent transition compositing. P07/P08 implement shared compositors; P15 does not claim transition visual parity. Portable hosted visual-asset/network isolation is handled by P17, not this local player.
